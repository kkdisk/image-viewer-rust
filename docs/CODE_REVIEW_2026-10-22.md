2026-10-22 再次核對外部審查摘要：請求編號隔離、直方圖背景化與持有 `Arc` 快照的判斷有程式碼依據，但外部報告的「44 項測試」不符合目前版本，目前為 48 項通過及 1 項預設忽略的效能量測。以下敘述應限縮：

- `cancel_archive_loading` 使結果失效並清理介面狀態，沒有終止正在執行的解壓，也沒有移除排隊任務；背景 CPU、磁碟使用及暫存資料仍會持續至工作完成與結果釋放。

五項問題已完成修正，以下原始審查內容保留作為問題依據；其中行號屬修正前版本。

- 保留原生 7-Zip 加速。原生程序只以 `-so` 傳回解壓資料，不直接建立檔案；Rust 在啟動前驗證全部條目的路徑、數量、單檔及總容量，再以固定大小緩衝區分流寫檔，逐檔確認長度及 CRC。不符合預期的額外串流不會落盤，程序會被結束並回收。
- 每個壓縮檔只啟動一次原生程序，避免逐檔解碼固實資料。缺少原生引擎、缺少可驗證 CRC、原生失敗或資料不符時，先清除原生暫存資料，再降級至受限純 Rust 引擎；退出碼 2 不再直接轉成密碼錯誤。純 Rust 引擎也先驗證全部標頭。
- 介面只接受目前壓縮檔請求的結果，一般圖片開啟、導覽及取消會使舊請求失效；等待函式以介面實際接收到的結果判斷完成。
- 放大鏡定位確保 `clamp` 上界不小於下界，涵蓋極小視口、臨界尺寸與正常尺寸的正式繪圖測試。
- 直方圖改由獨立背景工作計算，等待影像僅保留最新一張；介面以 `Arc` 快照身分過濾過期結果，等待期間仍能使用先前快取。

## 必須修正

1. **高優先：原生解壓完成後才檢查安全限制。** `crates/core-archive/src/archive.rs:508` 執行完整解壓，直到第 530 行才檢查容量與條目數。超過限制的壓縮檔已能先耗盡磁碟；非圖片也全部落盤。建議在啟動前驗證條目、路徑與宣告容量，並於解壓期間強制限制；若無法確實限制原生程序，應使用有受限串流的純 Rust 引擎。此項由控制流程確認，未實際執行大型解壓炸彈。

2. **高優先：舊背景結果覆蓋最新操作。** `crates/app-ui/src/app.rs:216` 未比對結果的請求編號，直接套用舊結果。已以臨時整合測試重現：送出壓縮檔 A → 開啟一般圖片 B → 輪詢 A 的結果，最終圖片變回 A。若 B 已開始編輯，其工作階段也會被替換。建議以共同的開檔世代編號涵蓋一般圖片與壓縮檔，忽略過期成功、錯誤及密碼要求；取消操作也需使舊請求失效。

3. **高優先：小視口的放大鏡會崩潰。** `crates/app-ui/src/canvas/magnifier.rs:66` 與第 67 行的下界為視口起點加 4，上界卻可能僅為視口起點，導致 `f32::clamp` 恐慌。以 100×100 視口呼叫正式繪圖元件已重現 `min = 4.0, max = 0.0`。視口寬度小於 204 或高度小於 256 時可進入此情況。建議縮小浮窗、空間不足時略過顯示，或讓上界至少等於下界；補上小尺寸與邊界測試。

4. **中優先：直方圖在介面執行緒同步計算。** `crates/app-ui/src/app.rs:451` 對每個新的預覽影像同步掃描全部像素，並由介面更新迴圈第 744 行呼叫。雖然內部使用 Rayon，呼叫端仍需等待全部統計與合併完成；大圖及滑桿預覽會阻塞介面，違反規格第 8 節的背景運算要求。建議以背景工作計算，附影像版本，只接收最新結果並保留上一份快取。未量測實際畫面更新率。

5. **中優先：原生 7-Zip 的所有致命錯誤被當成密碼錯誤。** `crates/core-archive/src/archive.rs:517` 將退出碼 2 一律轉成密碼例外；程式本身的註解也指出此碼包含一般致命錯誤與 CRC 錯誤。損毀或無法讀取的未加密壓縮檔因此會反覆要求密碼，且阻止純 Rust 降級。建議只在有明確密碼證據時回傳密碼例外，其餘保留診斷或交由純 Rust 引擎重新分類。

## 其他建議

- 放大鏡目前的採樣測試只呼叫 `RgbaImage::get_pixel`，倍率測試則在測試內重寫切換邏輯，未經過正式元件或快捷鍵處理，無法捕捉實際繪圖崩潰。
- 固實 7z 回歸測試透過自動選擇引擎的入口執行；安裝 7-Zip 的環境會走原生引擎，未驗證純 Rust 的串流對齊。建議可明確指定兩種引擎，並共用固定測資，分別覆蓋密碼、容量限制及非圖片條目。
- 任務紀錄宣稱 Fat LTO、單一編碼單元與終止式恐慌設定，但目前 `Cargo.toml` 使用 `lto = "thin"`、`codegen-units = 16` 且沒有 `panic = "abort"`。應對齊設定與驗收證據，再更新完工宣告。
