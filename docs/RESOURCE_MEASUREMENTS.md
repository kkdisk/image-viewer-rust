# 資源量測紀錄

日期：2026-10-22。Rust 1.99.1，Intel Core i7-9750H、RAM 34,152,423,424 位元組，Intel UHD Graphics 630／NVIDIA RTX 2060；驅動與原始數據分別見 [0.4.0 切片](performance/resource-baseline-v040.json) 與 [0.5.0 整合](performance/resource-baseline-v050.json)。

## 重現方法

在 Visual Studio C++ 開發者 PowerShell 執行：

```powershell
./scripts/measure_resources.ps1
```

腳本以發布模式執行預設忽略的 `resource_baseline` 測試，固定產生 1920×1080、6000×4000、30000×8 的單色 RGBA PNG。同次程序比較完整影像受 GPU 上限限制的策略與視口分級策略，模擬 1280×800 視口及 8192 GPU 上限；使用 egui CPU 紋理交付，沒有建立原生 GPU 視窗。取樣輸出寫入 `target/resource-baseline.json`，不改動使用者圖片。

以下為各案例單次樣本，不是多次平均或速度保證。檔案剛建立，因此解碼採暖檔案快取；首次紋理時間包含背景等待與一毫秒輪詢。CPU 幀 p95 只描述測試迴圈，不可當成原生 GPU 幀時間或 60 FPS 證據。

## 最終整合樣本

| 圖片 | 暖解碼 ms | 全圖／分級首次 CPU 交付 ms | 全圖／分級紋理估計位元組 |
|---|---:|---:|---:|
| 1920×1080 | 4.77 | 12.68／12.09 | 8,294,400／8,294,400 |
| 6000×4000 | 46.35 | 116.22／291.83 | 96,000,000／11,182,080 |
| 30000×8 | 1.11 | 5.94／4.33 | 65,536／8,192 |

分級降低大圖的顯示容量，6000×4000 案例因背景重採樣增加首次交付延遲；不能宣稱所有情境更快。最終程序取樣峰值工作集 298,647,552 位元組，包含測資建立、全圖對照及全部案例，不能視為分級模式的獨立峰值。先前切片為 393,768,960 位元組，因版本及配置差異，不以兩個單次總峰值推論穩定改善倍數。

以此機器與測資採保守預設：縮圖最多 16 MiB／512 筆，兩個解碼工作；每張顯示紋理最多 4096 單邊（RGBA 估計 64 MiB），仍取裝置上限較小者。這些是本機起始預設，非全程序硬上限或所有硬體的最優值。原生冷啟動、原生首次顯示及 GPU 幀時間為 **Unknown**，桌面驗收後再調整效能門檻。
