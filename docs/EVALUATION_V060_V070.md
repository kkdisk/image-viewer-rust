# 0.6.0／0.7.0 開發前評估

日期：2026-10-23。基線：0.5.2，提交 `3e70951`。本輪僅評估與整理規劃；下列新增預設值及演算法選擇為提案，尚未實作或驗收，不代表已承諾工期。

依據：[主規格](SPEC_RUST_IMAGE_VIEWER.md)、[路線圖第 6、7、11 節](ROADMAP.md)、[資源契約](SPEC_BROWSING_RESOURCES.md)及[高品質放大契約](SPEC_HIGH_QUALITY_ZOOM.md)。沿用快速看圖、偶爾微調的定位，維持 0.6.0 → 0.7.0 → 0.8.0 的順序。

## 1. 評估結論

- 0.6.0 可沿用既有影像、狀態與介面分層，先完成 P3 歷史記憶體預算與共用預覽契約，再實作裁切、改尺寸及明確輸出選項。整體規模偏大，最高風險在狀態、記憶體與寫檔失敗保護，而非裁切演算法。
- 0.7.0 沿用上述契約加入 RGB／通道曲線、參數預設集與一鍵自動校正。整體規模中至大，最高風險在預覽組合順序、過期結果及預設集相容性。
- 兩版第一階段均以既有依賴為目標；實作前再核對所需編碼器能力。不為本輪調整 Rust 版本、GUI 框架、檔案色彩空間或系統安全性原則。
- 0.5.2 使用者回報重建成功；不能因此推論工作區測試、遠端 CI、最新封裝或原生桌面驗收全部通過。開發基線驗證與後續版本驗收分別記錄。

## 3. 0.6.0：歷史預算、幾何編輯與輸出

### 3.1 P3 歷史記憶體預算：先行完成

- 保留 20 步作為步數上限，另外加入軟記憶體預算。預設候選值為 512 MiB，須以固定測資量測後定案；本輪不加入設定視窗。
- 按共享影像配置識別去重；統計過去、目前、未來節點及 Session 原圖的持有關係。同一 `Arc` 多次出現只計一次，不對完整像素雜湊。
- 新提交先清除重做分支，再按最舊可復原節點汰換。復原／重做只移動節點，不應因移動本身失去相反操作；調低預算時的重做汰換順序須寫入正式規格。
- 必要原圖與目前底圖保留；預覽及正在運算的來源另列用量，不宣稱涵蓋全部程序。必要影像本身超限時明確提示，禁止自動改為磁碟 Undo 或降低底圖解析度。
- 儲存點以節點 ID 判定。已儲存節點被汰換後保留識別語意，不把相同像素或另一分支誤當已儲存；介面顯示可用復原／重做步數與預算限制。

容量例：64 × 1024 × 1024 像素的 RGBA8 快照為 256 MiB；20 張不同快照約 5 GiB。原圖、底圖、預覽若各有不同配置，三張就約 768 MiB，尚未計入工作中間值及 GPU 紋理。因此 512 MiB 只能是軟預算候選，不能作程序硬上限。

### 3.2 共用編輯與背景契約

- 建議一次啟用一種編輯工具。切換工具、切圖、離開全螢幕、開啟比較或儲存遇到未套用草稿時，依明確的套用／捨棄／取消流程處理；不得沿用 `push_action` 的隱式清除作為工具切換政策。
- 草稿記錄文件世代、已提交節點識別、操作參數及請求版本。來源指標可輔助檢查，不能單獨區分引用相同影像的不同節點。
- 每個文件最多一項執行中及一項最新等待的像素工作，完成結果也有界；取消只保證不提交過期結果，除非另加合作式檢查，不能宣稱已停止所有運算。
- 預覽不改歷史；套用時僅接受最新、完整像素結果，新增一個歷史節點。計算未完成不得儲存顯示縮圖或過期預覽。
- 草稿、底圖、儲存狀態及來源路徑各自管理；所有新草稿都納入既有離開保護，不能僅依 `AdjustmentParams::is_identity()` 判斷。

### 3.3 裁切與改尺寸

- 首版裁切：自由、原比例、1:1、4:3、3:2、16:9；支援移動、邊角拖曳及整數像素數值輸入。先不做透視或任意角度拉正。
- 使用 EXIF 已校正、當前已提交影像的座標。整數範圍採左上含、右下不含；將反向拖曳正規化，起點向下、終點向上取整後限於影像內，拒絕空範圍。固定比例於整數化後允許最多一像素取整誤差，介面顯示實際尺寸。
- 縮放、平移、DPI、部分紋理及縮圖層級都只影響顯示換算。以完整已提交影像做裁切；一像素區域、四邊、超出畫布及縮小視圖均須驗證。
- 裁切草稿先以遮罩與框線顯示；套用才於背景產生完整裁切像素。首版建議編輯工具與雙圖比較互斥，套用後重設適合視窗；原圖比較仍顯示完整開啟原圖，不宣稱裁切後座標已對齊。
- 改尺寸提供寬／高、鎖定比例及百分比；最終寬高至少為 1，先以寬整數運算驗證溢位與現有 64M 像素上限，再配置輸出。鎖定比例時明確定義哪個欄位為主值與取整規則。
- 建議預設雙三次取樣，保留最近鄰供像素圖使用；透明圖應採預乘 Alpha 的處理策略，避免隱藏 RGB 滲邊，並驗證不透明／半透明邊界。不能直接假設目前顯示取樣可完整重用為全圖輸出。
- 「改尺寸」是可復原的編輯，與匯出時的格式／品質不同；0.6.0 先不增加另一套僅匯出改尺寸流程。

### 3.4 輸出契約

- 首批明確選項以 PNG、JPEG 為核心；既有其他格式入口先保留相容行為並逐一核對編碼能力，不能把「可解碼」當成「有該格式品質選項」。
- 新輸出入口必須明確決定格式與副檔名；未知副檔名不得默默輸出 PNG。明確 JPEG 品質範圍 1–100，候選預設 90，正式規格須說明與既有 JPEG 行為的差異。
- PNG 保留透明度。透明轉 JPEG 必須明示合成背景，候選預設白色；採何種數值空間合成與取整需固定測資驗證，不藉此更動整個專案色彩空間預設。
- 「儲存／另存」成功後才更新來源及已儲存節點；「匯出副本」僅輸出目前已提交影像，不改來源、歷史或未儲存標記。失敗及取消均保留原狀。JPEG 重新壓縮及動畫轉靜態警告繼續適用。
- 首版不複製來源 EXIF、GPS、縮圖或未知 ICC，方向已烘焙於像素；輸出選項清楚說明不保留來源元資料，不虛設「保留」開關。隱私驗收需以含 GPS／方向標籤的測資重讀輸出確認，不能只靠程式碼推論。
- 一般另存／匯出遇既有檔案須確認；壓縮來源強制另存外部，拒絕任何寫入受管理解壓根目錄的路徑。
- 擴充既有同目錄暫存流程。現行 `persist` 失敗的備份／交換分支需另審：還原失敗不得忽略或讓唯一備份隨暫存物件清理而消失。驗收涵蓋編碼、替換、還原失敗，不將備份交換描述為完全無間隙的原子替換。

## 4. 0.7.0：曲線、預設集及自動校正

### 4.1 曲線與共用預覽

- 首版為 RGBA8 資料上的 RGB 總曲線及 R／G／B 通道曲線，Alpha 不變；不增加 RAW、HDR、16 位元或完整 ICC 色彩管理。
- 提案採分段線性曲線，先確保穩定且可驗證；控制點的輸入位置嚴格遞增、端點存在、值域合法、數值有限。拒絕同位置重複點及非法預設集，輸出值可遞減以支援反相。
- 以 256 項查表映射各通道，固定取整規則；恆等曲線逐位元組不變，透明像素的 Alpha 也須保持。每張圖仍需完整逐像素處理，不宣稱查表可使整圖運算成固定成本。
- 同一調色草稿包含微調及曲線。候選順序為既有微調 → RGB 總曲線 → 各通道曲線，每次從同一已提交底圖計算，禁止在前一張預覽上重複套用。
- 曲線 UI 提供新增／移動／刪除控制點、通道切換、重設及預覽比較；鍵盤輸入有焦點時不得觸發切圖快捷鍵。延用 0.6.0 的有界安排與過期結果隔離，套用一次只新增一個歷史節點。

### 4.2 預設集

- 只保存微調、曲線與演算法版本等可重用參數；不包含像素、來源路徑、裁切座標、圖片尺寸或歷史節點。首版採使用者明確匯入／匯出的版本化 JSON，避免先建立另一套共用預設集資料庫。
- 記錄結構版本、名稱及參數；載入後先驗證版本、數值、控制點數與檔案大小，未知新版或損毀檔案不覆蓋現有草稿。限制值於正式規格定案。
- 選取預設集只產生預覽，套用才進入歷史。匯出採背景同目錄暫存替換，遇已存在檔案明確確認，失敗保留原檔。

### 4.3 自動色階與自動白平衡

- 兩者都是「產生可調整預覽」，不能直接改底圖或儲存檔。自動色階建議先以亮度分位數產生總曲線，避免首版對三通道各自拉伸造成額外色偏。
- 自動白平衡先評估有效像素的通道統計估計，再映射到既有色溫／色調或新增明確增益參數；兩者表達能力不同，不能承諾現有兩參數能精確表示任意通道增益。
- 完全透明像素排除；半透明採何種權重須固定。全透明、純黑、單色或有效樣本不足時回傳不變結果並提示；對極端增益設限，禁止除零、非有限值或全圖飽和。
- 需要灰階、偏色、低對比、透明及極端曝光的固定測資與主觀比對。若品質不足，自動校正移至 0.7.x，曲線及預設集可獨立驗收。
- 銳利化、降噪及其他鄰域濾鏡保留 0.7.x 候選，不擴大本版核心範圍。

## 7. 正式規格需定案的提案

- P3 軟預算候選 512 MiB、重做分支在調低預算時的汰換順序及提示文案。
- 首版裁切比例、工具與比較互斥、尺寸取整及原圖比較行為。
- 新 JPEG 輸出品質候選 90、透明背景候選白色，以及既有儲存與新匯出入口的相容政策。
- 分段線性曲線、組合順序、預設集限制，以及自動校正退化輸入和品質門檻。

上述可在正式規格階段採用或修訂；涉及主規格要求先確認的色彩空間預設變更或 C/C++ 外部動態依賴時，仍須依主規格處理。本輪不觸及這些變更。
